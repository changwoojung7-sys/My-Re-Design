# 📢 [업데이트] v2.1.5 (Version Code 35) 배포 안내

안녕하세요, **My Re Design**입니다!
안드로이드 앱에서 결제 완료 후 로그아웃되거나 구독 정보가 저장되지 않던 심각한 버그를 수정한 **v2.1.5** 업데이트를 배포했습니다.

### 💳 안드로이드 결제 후 로그아웃 & 구독 미저장 오류 수정

#### 1. 결제 완료 후 자동 로그아웃 문제 해결

* **문제**: 안드로이드 앱에서 결제 완료/취소 후 앱으로 돌아올 때 로그인이 풀리는 현상. 웹에서는 정상 동작.
* **원인**: `MainActivity.java`에서 결제 후 앱 복원 시 `http://localhost`로 WebView를 로드했는데, Capacitor의 실제 origin은 `https://localhost`임. 이 두 origin은 브라우저 보안 정책상 완전히 별개의 localStorage를 사용하므로 Supabase 세션 토큰(`sb-*-auth-token`)이 보이지 않아 자동 로그아웃 발생.
* **수정 사항**: `MainActivity.java`의 팝업 WebView, 메인 WebView, `restoreApp()` fallback 등 모든 URL 로드를 `https://localhost`로 통일.

#### 2. 결제 결과 누락 문제 해결

* **문제**: 결제 성공/실패 정보가 앱에 전달되지 않아 구독이 활성화되지 않는 현상.
* **원인**: Java가 결제 결과를 `localStorage`에 저장했으나, React는 URL 파라미터(`?payment_result=...`)만 파싱해서 결과가 누락됨.
* **수정 사항**: Java에서 결제 결과를 `https://localhost/?payment_result=...` URL 파라미터 방식으로 전달하도록 통일.

#### 3. 세션 복원 타이밍 문제 해결

* **문제**: 결제 후 앱 재초기화 시 Supabase 세션 복원 전에 결제 처리가 실행되어 DB 저장 실패.
* **수정 사항**: `App.tsx`에서 결제 처리 전 세션 복원 대기 폴링(500ms × 최대 12회)을 추가. 세션이 확인된 후 결제 처리를 진행.

#### 4. V1/V2 결제 판정 로직 개선

* PortOne V1(`imp_success`, `imp_uid`, `merchant_uid`)과 V2(`paymentId`, `code`) 파라미터를 모두 올바르게 처리하도록 `App.tsx` 결제 성공/실패 판정 로직 개선.

### 🚀 버전 정보

* **Version Name**: `2.1.5`
* **Version Code**: `35`

### 🔄 미션 새로고침(Refresh) 동기화 완료

* **수정 사항**:
  * 기기 내부 저장소(LocalStorage)에 의존하던 방식을 버리고, **Supabase DB(`mission_refresh_log`)를 직접 참조**하여 동기화하는 방식으로 서버-클라이언트 통신 구조를 전면 개편했습니다.

* **효과**: 어느 기기로 접속하든 정확한 잔여 새로고침 횟수를 확인할 수 있으며, 미션 변경이 실시간으로 동기화됩니다.

### 🎮 FunPlay 미션 대규모 확장

#### 2. FunPlay 미션 3개 동시 생성 및 패턴 확장

* **기존**: FunPlay 카테고리는 가벼운 미션 1개만 생성되며, 패턴(Archetype, Twist 등)이 5~10개 수준에 머물러 있어 며칠 후 반복되는 느낌이 있었습니다.
* **수정 사항**:
  * **미션 3개 생성**: 다른 핵심 미션들과 동일하게, FunPlay에서도 한 번에 **3개의 미션**을 제공하여 선택의 폭을 넓혔습니다.
  * **난이도 시스템 및 패턴 대폭 확장**: AI가 미션을 생성할 때 쓰는 패턴 라이브러리를 `Easy`, `Medium`, `Hard` 3단계 난이도로 분리했습니다.
  * Archetype(테마) **30개**, Mechanic(제약 조건) **37개**, Twist(변형) **30개**로 기존 대비 **10배 이상** 패턴 풀을 확장했습니다. (조합 가능 수 10,000개 이상)
* **효과**: 매일 전혀 다른 난이도와 테마의 신선하고 기발한 FunPlay 미션을 3개씩 받아보며 일상의 소소한 재미를 무한대로 즐기실 수 있습니다.

### 💸 무료 체험자(Trial) 미션 수익화 로직 개선

#### 3. 페이월(Paywall) 시점과 미션 생성 순서 교정

* **기존**: 무료 체험 Phase 4 단계에서 리워드 광고를 시청하지 않았음에도 AI가 백그라운드에서 미션을 미리 생성해버려 호출 자원 낭비 및 로직 꼬임이 있었습니다.
* **수정 사항**:
  * 미션을 서버에 요청하기 전에 페이월(광고/구독 확인) 방어막이 완벽히 작동하도록 가드(Guard) 로직(`shouldBlockForPaywall`)을 추가했습니다.
